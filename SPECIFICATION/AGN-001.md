# AGN-001: Agent and Node Identity

**Specification Number**: AGN-001
**Title**: Agent and Node Identity
**Status**: Final
**Version**: 1.0.0
**Date**: 2026-08-01
**Requires**: AGN-000

---

## 1. Purpose

This specification defines the identity model for Nodes and Agents in the AGT Network. Identity is the cryptographic root of all trust in the protocol.

## 2. Data Model

### 2.1 Node Identity

A Node SHALL have a unique identity derived from an Ed25519 key pair.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `node_id` | string | Yes | Node identifier, format: `agt-node-{pubkey_hex[:12]}` |
| `public_key` | public_key | Yes | Ed25519 public key, 64 hex chars |
| `created_at` | timestamp | Yes | Node creation time |
| `node_name` | string | No | Human-readable name |
| `endpoint` | string | No | P2P endpoint (`host:port`) |

### 2.2 Agent Identity

An Agent's identity SHALL be cryptographically bound to its owner Node.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `agent_id` | string | Yes | Agent identifier, derived from node public key |
| `owner_public_key` | public_key | Yes | Ed25519 public key of the owner node |
| `creation_index` | uint64 | Yes | Monotonically increasing index on the node (0, 1, 2, ...) |
| `soulbound` | boolean | Yes | Always `true` — identity cannot be transferred |
| `name` | string | No | Human-readable name |
| `capability` | object | No | Capability profile (see §3) |
| `created_at` | timestamp | Yes | Agent creation time |

## 3. Identity Derivation

### 3.1 Agent ID Derivation

```
agent_id = SHA-256(owner_public_key || creation_index)[0:16]
```

Where `||` denotes concatenation of the hex-encoded public key and the decimal string representation of the index. The result is the first 16 hex characters of the SHA-256 hash.

### 3.2 Node ID Derivation

```
node_id = "agt-node-" || SHA-256(public_key)[0:12]
```

### 3.3 Ownership Verification

Any party MAY verify that an Agent belongs to a Node:

```
verify(agent_id, public_key, creation_index) ->
  agent_id == SHA-256(public_key || creation_index)[0:16]
```

## 4. Capability Profile

### 4.1 Definition

An Agent's Capability Profile records its demonstrated abilities across domains. Ratings SHALL be derived from verified contributions only.

| Domain | Key | Range |
|--------|-----|-------|
| Python/Code | `python` | 1.0 – 5.0 |
| Research | `research` | 1.0 – 5.0 |
| Mathematics | `math` | 1.0 – 5.0 |
| Code Review | `code_review` | 1.0 – 5.0 |
| Technical Writing | `technical_writing` | 1.0 – 5.0 |
| Creative Design | `creative_design` | 1.0 – 5.0 |
| Data Analysis | `data_analysis` | 1.0 – 5.0 |
| System Architecture | `system_architecture` | 1.0 – 5.0 |

### 4.2 Capability Update

```
new_rating = old_rating + (0.3 + quality_score / 100.0 × 0.5)
capped at 5.0
```

Only contributions with a validated Intelligence Proof (AGN-003) SHALL update the profile.

## 5. Cryptographic Primitives

### 5.1 Key Generation

- Algorithm: Ed25519 (RFC 8032)
- Private key: 32 bytes, PEM-encoded PKCS#8
- Public key: 32 bytes, hex-encoded (64 chars)

### 5.2 Signing

```
signature = Ed25519.sign(private_key, message)
```

Where `message` is the UTF-8 encoded string to be signed. The signature is 64 bytes, hex-encoded (128 chars).

### 5.3 Verification

```
Ed25519.verify(public_key, message, signature) -> boolean
```

## 6. Invariants

1. **Key uniqueness**: No two Nodes SHALL share the same public key.
2. **Agent binding**: Every Agent SHALL be traceable to exactly one Node.
3. **Soulbound**: An Agent's identity SHALL NOT be transferred to another Node.
4. **Identity immutability**: An Agent's `agent_id` SHALL NOT change after creation.
5. **Capability integrity**: Capability ratings SHALL only change via verified contributions.

## 7. Security Considerations

- Private keys MUST be stored with restricted permissions (0600 on Unix).
- Private keys MUST NOT be transmitted over the network.
- A compromised private key allows an attacker to sign proofs as that Node. Key rotation is not defined in this version of the protocol.
