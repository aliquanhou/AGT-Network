# AGN-006: P2P Protocol

**Specification Number**: AGN-006
**Title**: Peer-to-Peer Network Protocol
**Status**: Final
**Version**: 1.0.0
**Date**: 2026-08-01
**Requires**: AGN-000, AGN-001

---

## 1. Purpose

This specification defines the P2P communication protocol for AGT Network nodes. v1.0 uses UDP multicast discovery and WebSocket direct communication. Future versions (v2.0+) will upgrade to libp2p.

## 2. Message Types

| Type | Direction | Description |
|------|-----------|-------------|
| `NODE_ANNOUNCE` | Broadcast (UDP) | Node advertises its presence |
| `NODE_QUERY` | Request (WS) | Query a node for its status |
| `NODE_RESPONSE` | Response (WS) | Response to NODE_QUERY |
| `TASK_BROADCAST` | Broadcast (WS) | A new task is available |
| `TASK_CLAIM` | Request (WS) | Claim a task for execution |
| `TASK_RESULT` | Response (WS) | Submit task execution result |
| `CONTRIBUTION_BROADCAST` | Broadcast (WS) | An Intelligence Proof has been generated |
| `VALIDATOR_REQUEST` | Request (WS) | Request validation of a result |
| `VALIDATOR_RESPONSE` | Response (WS) | Validator's assessment |

## 3. Message Format

All messages SHALL be JSON objects:

```json
{
    "type": "MESSAGE_TYPE",
    "node_id": "sender-node-id",
    "timestamp": 1234567890.123,
    "msg_id": "unique-message-id",
    "payload": {}
}
```

## 4. Discovery Protocol (v1.0 — UDP Multicast)

### 4.1 Constants

```
MULTICAST_GROUP = "239.255.0.1"
MULTICAST_PORT = 9999
ANNOUNCE_INTERVAL = 5.0 seconds
PEER_TIMEOUT = 30.0 seconds
```

### 4.2 Announcement

Every node SHALL broadcast a `NODE_ANNOUNCE` message every `ANNOUNCE_INTERVAL` seconds via UDP to the multicast group.

```json
{
    "type": "NODE_ANNOUNCE",
    "node_id": "agt-node-abc123...",
    "host": "192.168.1.100",
    "port": 8001,
    "node_name": "My AGT Node",
    "timestamp": 1234567890.123
}
```

### 4.3 Peer Tracking

A peer is considered ACTIVE if its last announcement was received within `PEER_TIMEOUT` seconds. A peer is considered OFFLINE if no announcement has been received for more than `PEER_TIMEOUT` seconds.

### 4.4 Upgrade Path

```
v1.0: UDP Multicast (local network only)
v2.0: libp2p (cross-network DHT discovery)
v3.0: AGT P2P Protocol (custom discovery + relay)
```

## 5. Direct Communication (WebSocket)

### 5.1 Connection

Nodes establish direct WebSocket connections at `ws://{host}:{port}/ws`.

### 5.2 Identity Handshake

Upon connection, the client SHALL immediately send its node identity:

```json
{
    "type": "NODE_ANNOUNCE",
    "node_id": "connecting-node-id",
    "payload": {
        "host": "192.168.1.100",
        "port": 8001
    }
}
```

The server SHALL use this to identify the connecting peer. Connecting to oneself SHALL be rejected.

### 5.3 Message Integrity

All WebSocket messages SHALL be valid JSON. Invalid messages SHALL be logged and discarded. Messages that fail Ed25519 signature verification SHALL be discarded with a warning.

## 6. Signed Messages (v1.0+)

All P2P messages MAY include an Ed25519 signature:

```json
{
    "...": "...",
    "signature": "hex-encoded-ed25519-signature",
    "public_key": "hex-encoded-ed25519-public-key"
}
```

The signature covers the SHA-256 hash of the message body (excluding the signature field itself).

## 7. Invariants

1. **Self-connection**: A node SHALL NOT connect to itself.
2. **Identity**: Every connection SHALL identify the peer via a handshake message.
3. **JSON**: All messages SHALL be valid JSON.
4. **Discovery separation**: UDP discovery and WebSocket communication SHALL be independent — discovery introduces peers, WebSocket connects them.
